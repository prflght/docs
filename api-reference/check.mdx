`POST /check` is the core Prflght endpoint. Submit a serialized Solana transaction and Prflght will simulate it, evaluate it against your policy, check the health of any DeFi protocols involved, and return signed ed25519 attestation instructions to prepend before sending on-chain.

## Endpoint

```
POST https://api.prflght.xyz/check
```

## Authentication

Pass your API key in the `x-api-key` request header. Get your API key from the **API Keys** section of [app.prflght.xyz](https://app.prflght.xyz).

```bash
x-api-key: <your PRFLGHT_API_KEY>
```

## Request body

<ParamField body="tx" type="string" required>
  Base64-encoded serialized Solana `VersionedTransaction`. Serialize using `transaction.serialize()` then encode with `Buffer.from(...).toString('base64')`.
</ParamField>

<ParamField body="agentId" type="string" required>
  Your agent's wallet public key as a base58 string. Included in the on-chain attestation so the program can verify the correct agent signed.
</ParamField>

### Request example

```json
{
  "tx": "AQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAACAAQAHDg...",
  "agentId": "4sGjMW1sUnHuiSFRhCAUt3pCkTaLRF1rBDUBGfVXvBb3"
}
```

## Response fields

Prflght returns one of two decision shapes: `allow` or `deny`.

### Allow response

<ResponseField name="decision" type="string" required>
  `"allow"` - the transaction passed simulation, policy evaluation, and protocol health checks.
</ResponseField>

<ResponseField name="policyHash" type="string" required>
  Hex string identifying the exact policy version evaluated. Use for audit trails.
</ResponseField>

<ResponseField name="expiry" type="number" required>
  Unix timestamp (seconds) after which the attestation is no longer valid. Submit the transaction on-chain before this time.
</ResponseField>

<ResponseField name="attestationIxs" type="array" required>
  Instruction objects to prepend to your transaction before submitting. Each instruction has:

  <Expandable title="attestationIxs item">
    <ResponseField name="programId" type="string" required>
      The Prflght on-chain program ID: `3JxoMhdGbnGx4eTvZ9nagSBdoWu1okd1Sf5VA3eRyKfo`
    </ResponseField>
    <ResponseField name="accounts" type="array" required>
      Account metas required by the attestation instruction.
    </ResponseField>
    <ResponseField name="data" type="string" required>
      Base64-encoded instruction data containing the signed attestation payload.
    </ResponseField>
  </Expandable>
</ResponseField>

### Deny response

<ResponseField name="decision" type="string" required>
  `"deny"` - the transaction was blocked.
</ResponseField>

<ResponseField name="reason" type="string" required>
  Human-readable explanation of why the transaction was denied. For example: `"notional $15000 exceeds policy max $10000"`.
</ResponseField>

<Warning>
  You must prepend every instruction in `attestationIxs` to your transaction before submitting. The on-chain program verifies the attestation as the first step - if the instructions are missing or placed after your other instructions, the transaction is rejected.
</Warning>

<Note>
  Transactions are denied for one of three reasons: a policy violation (notional limit, disallowed program, or daily cap exceeded), a protocol health check failure (venue health score below your threshold), or a simulation failure (the transaction would revert on-chain). The `reason` field tells you which condition triggered the block.
</Note>
